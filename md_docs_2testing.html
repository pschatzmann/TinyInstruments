Testing

The core does not depend on Arduino, so it can be built and tested on the desktop with CMake:

cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure

test_voice pitch, loops, decay, release, stereo
test_synthesizer midi handling, polyphony, voice stealing, sustain, choke groups, instrument bank and program changes

test_drums drum kit: General MIDI keys, one shots, hi-hat choke, groove
test_sax saxophone: pitch and octave, sustain, monophonic, legato, vibrato, breath
test_loader loading the data/*.bin files, chunked streams, errors
test_clarinet clarinet: pitch and octave, corrected root key, sustain, legato, no automatic vibrato
test_psola PSOLA: lossless at ratio 1, pitch, length kept (amplitude step), continuity, level, loops, one shots, legato start, formants kept with the real clarinet
test_small small sample sets: size, binary files, every key compared with the full version, pitch
test_jazz electric piano and upright bass: sizes, headers identical with the data files, every key sounds, pitch, velocity, release, 4 strings; tremolo (auto pan)
test_organ tonewheel organ: pitch of the drawbars, foldback, sustain, release, percussion (single triggered), drawbars with CCs; rotary speaker: stereo, slow and fast modulation, acceleration
test_octave octave sample sets: size, headers identical with the data files, every key sounds, pitch
test_forwarders midi forwarding of the desktop player: serial (pseudo terminal, 115200 and 31250 baud), TCP with reconnect, UDP, target parsing (POSIX only)
test_midi_file midi files of the desktop player: tracks of a format 1 file merged, tempo map, 120 BPM default, invalid files, the example song of arduino-midi-fileparser (4781 notes, 3:54); GeneralMidiBank mapping (only built if ../arduino-midi-fileparser exists)
test_bass bass: pitch and octave down to the low E, bass amp keeps the low end, 4 strings, palm mute
test_guitar guitar: pitch, all keys, amp distortion per preset, echo tail, effect only on its channel, palm mute, midi control

To listen to the result, render a demo of all instruments to a wav file:

./build/tests/render_demo demo.wav

The example recordings of the README (docs/audio) are rendered from the data files with the same phrase for all versions of an instrument:

./build/tests/render_examples /tmp/examples
for f in /tmp/examples/*.wav; do
ffmpeg -i "$f" -codec:a libmp3lame -b:a 96k "docs/audio/$(basename "${f%.wav}").mp3"
done

Running the examples on the desktop

All example sketches also build and run unchanged on the desktop with the Arduino-Emulator:

cmake -S . -B build-examples -DTI_BUILD_EXAMPLES=ON
cmake --build build-examples
./build-examples/examples/piano-demo
ctest --test-dir build-examples -L examples # each sketch must run for 3 seconds

The examples are not built by default (TI_BUILD_EXAMPLES=OFF). Requirements: CMake 3.16+, a C++17 compiler, a sound card, internet access for the first build and, for material-gui, SDL2 (sudo apt install libsdl2-dev; without SDL2 material-gui is skipped). USB midi uses the ALSA raw midi devices (/dev/snd/midiC*D*) of arduino-midi, so it is only available on Linux. Tested on Linux.

The sketches contain no desktop specific code. The platform specific parts are provided by the libraries and, for the hardware of material-gui, by desktop/emulator, which is only used by this build:

Serial midi on the desktop, e.g. a note on for C4:

printf '\x90\x3c\x64' | ./build-examples/examples/piano-serial-midi

To play material-gui with a USB midi keyboard, connect the keyboard to the computer and switch on the "USB" midi input on the Setup page; piano-usb-midi uses the keyboard directly. The first device in /dev/snd/midiC*D* is used (your user needs access to it, usually the audio group), and it is opened again when the keyboard is plugged in later. Raw midi devices are hardware (or snd-virmidi) ports: for a DAW or a midi file use the desktop player with --send tcp:localhost and the "TCP" input of material-gui, or pipe the midi into the "Serial" input. The sketches are compiled with HOST (like the Arduino-Emulator itself), which selects the desktop implementations of arduino-midi.

arduino-audio-tools, arduino-midi, arduino-midi-fileparser, TinyMaterialDesign and TinyGPU are used from the sibling directories (Arduino libraries folder) if available, otherwise they are downloaded together with the Arduino-Emulator and miniaudio. Use -DFETCHCONTENT_SOURCE_DIR_ARDUINO_EMULATOR=<dir> for a local checkout of the Arduino-Emulator.

The CPU load on a microcontroller is measured with the benchmark example (see Performance).
